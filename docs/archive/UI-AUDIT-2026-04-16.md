# Skedaddle Portal — UI audit (2026-04-16)

Live target: `https://www.skedaddleinc.com` (apex redirects to `www`). Authenticated session: Overwatch (Alex), Playwright storage at `docs/audit-storage/overwatch-state.json` (gitignored, **not** committed). Screenshots under `docs/audit-screenshots/` (gitignored).

## Methodology

- **Anonymous pass (accepted earlier):** Headless Chromium, no storage; captured login guard states and `/intake/mechanic`. Filenames like `landing-login__…`, `mechanic-intake__…`, `*-guard__…`.
- **Authenticated pass (this run):** Storage state with **`indexedDB: true`** (required for Firebase Auth). Headless captures after `localStorage` key `skedaddle-theme` + full reload per theme (**light** / **dark**) to match in-app `PortalChrome` behavior. Viewports **1440×900** and **390×844**.
- **Document-level overflow:** For each capture, `scrollWidth` vs `clientWidth` on `documentElement` (inner tables may still scroll horizontally without changing document width — called out as a blind spot).
- **Not performed:** Lighthouse lab scores, WCAG contrast tooling, keyboard-only walkthrough, slow-3G replay on authenticated pages, Slack-side previews.

## Executive Summary

The signed-in portal shell is coherent in **light** and **dark** with **no document-level horizontal overflow** on the routes we captured. **Tires**, **Rubber CRM** (board, leads, DJ Dispatch), **People**, **Analytics** (wall, metrics, revenue, leaderboard), and **Ops** all rendered with stable URLs on `www.skedaddleinc.com`. The largest liability observed in this pass is **`/dispatch`**: it replaces the window with the configured Workforce URL, which currently returns **Vercel 404**, so the “Launch Dispatcher” path is **broken in production**. Secondary risks are **large JS bundle** (Vite warns >500 kB gzip) and **wide tables** (`min-w-*` in source) that can still force **internal** sideways scrolling on small viewports even when the document width matches the viewport.

## Feature utilization gaps

- **Morning Brief:** Primarily Slack-driven per `docs/AI-CONTEXT.md`; no dedicated Wall sub-panel surfaced in this audit beyond existing Analytics Wall.
- **`/dispatch` → Workforce:** Intended bridge to external dispatcher; **currently 404** — highest-impact “built path but fails in prod” gap.
- **Listing Generator:** Lives behind catalog selection + **Generate listings** (`TiresDashboard.jsx`); not isolated as its own URL — consider a follow-up capture session that opens the modal for marketing evidence.
- **Keyboard shortcuts / command palette:** `PortalChrome` includes command palette wiring; discoverability not validated in this automated pass.

## Design system observations

- **Crew tags:** Centralize via `src/utils/portalCrewTag.js` (per AGENTS.md); spot-check CRM/People screenshots for raw role strings (none flagged from filenames alone).
- **Tables:** Repeated pattern of **`w-full` + `min-w-[…]`** for data density — consider a shared **responsive data grid** primitive with documented mobile behavior (scroll vs collapse).
- **Theme:** `skedaddle-theme` in `PortalChrome.jsx` is the single source of truth for in-app light/dark (not OS `prefers-color-scheme` for portal chrome).

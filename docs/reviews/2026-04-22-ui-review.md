# UI review - portal, April 22 2026

## 1. Snapshot

The portal has a confident, opinionated dark aesthetic and the Precision Cockpit dashboard largely lives up to its brief - the single emerald "hot" revenue hero is a nice focal point and the `pc-card` hover-bloom gives cards real identity. Outside the dashboard the language fragments: order cards, CRM kanban, Analytics, and Tires all reinvent the same primitives (badges, card radii, label casing, uppercase eyebrow sizes) so the app reads as five products in a trench coat. The biggest pattern conflicts are (a) three competing "uppercase eyebrow" scales (`text-[9px]`, `text-[10px]`, `text-[11px]`, each with different tracking), (b) two parallel button vocabularies (`BTN_PRIMARY` amber vs. ad-hoc zinc-100 "white" buttons like the Generate listings / Add VIP client CTAs), and (c) a dashboard that uses `bg-zinc-900/60` cards while every other module uses `bg-zinc-900/40` + `border-zinc-800` - visually they look like different apps.

## 2. Top 10 improvements

### 1. Unify the primary-CTA style across modules
- **Location:** `src/components/ui/buttonStyles.js:12`; competing styles at `TiresDashboard.jsx:1074` (`bg-zinc-100 text-zinc-950`), `CrmPage.jsx:602`, `OrdersList.jsx:817`, `LoginForm.jsx:71`, `PeopleDashboard.jsx:538` (violet primary).
- **Problem:** The same screen can show a white "Generate listings", an amber `BTN_PRIMARY` "Log sale", a violet "Add crew member", and a sky "Quote" button side-by-side. Users cannot tell which action is the recommended one, and the amber-500 defined as primary rarely wins.
- **Fix:** Pick one primary color (amber is the declared brand accent - keep it) and replace `bg-zinc-100 text-zinc-950` primary CTAs with `BTN_PRIMARY`. Relegate white/zinc-100 to "confirm-in-modal" only.
- **Effort:** M · **Impact:** high.

### 2. Collapse three eyebrow label scales into one token
- **Location:** `TodayStrip.jsx:5` (`text-[9px]` tracking 0.12em), `AnalyticsPage.jsx:490/822` (`text-[10px]` tracking wide), `OrdersList.jsx:707` (`text-[10px]`), `CrmPage.jsx:607` (`text-[10px]`), `ModuleSubheader.jsx` (tab labels `text-sm`).
- **Problem:** The 9 px Dashboard eyebrow reads as a different product than the 10 px Analytics eyebrow and the 11 px uppercase filter labels. It is also below the WCAG readable-minimum at 9 px.
- **Fix:** Introduce one utility - `.pc-eyebrow` at `text-[11px] font-semibold uppercase tracking-[0.1em] text-zinc-500` - and sweep all small-uppercase headers to it.
- **Effort:** S · **Impact:** med.

### 3. Give Tires' sticky control bar real visual weight
- **Location:** `TiresDashboard.jsx:870` (sticky container), `:886` (search input), `:909` (Filters button).
- **Problem:** The sticky "search + filters + sort + columns + export" stack is 4 rows tall on mobile and competes with the global `ModuleSubheader`; on desktop it floats mid-screen with only a subtle border. The selection action bar (Generate / Quote / Log sale / Notify / Prospective / Clear / Bulk overhead) produces 7 buttons on one row with 5 different border colors.
- **Fix:** Move secondary controls (Columns, Export CSV, Haggle slider) into a single "Table options" popover and group selection actions into "Selling actions" (primary amber split-button) + "Admin actions" (ghost menu). Raise the sticky bar's background to `bg-zinc-900/80` with a thin bottom shadow so it reads as a toolbar, not a floating note.
- **Effort:** L · **Impact:** high.

### 4. Orders card: fix the duplicate "Send update" button
- **Location:** `OrdersList.jsx:736-752`.
- **Problem:** When `customerNotifiedAt` is falsy the layout renders a primary "Send update". When truthy it renders "Mark complete" AND a secondary "Send update" - but the conditional also shows "Send reminder". The net effect is two "Send update" paths can appear and the button order changes based on state, which is disorienting.
- **Fix:** Render one "Send update" button (primary before notify, secondary after) and always place "Send reminder" next to it. Use a single action-row component that takes state as input, rather than three chained ternaries.
- **Effort:** S · **Impact:** med.

### 5. CRM kanban cards overflow on mobile and hide critical value
- **Location:** `CrmPage.jsx:778-840`.
- **Problem:** Each kanban card stacks name → stage → Next → Last note → $ → score chip → pain - 6+ lines at 10 px in a 2-char-wide column on mobile accordion view. Stage label repeats the column header. Score + pain chips fight the amber deal-value line for the eye.
- **Fix:** Reduce card to 3 lines by default (company + deal value + next-due status as a colored dot) with hover/tap expanding to full detail. Drop the redundant stage label inside the card. Promote deal-value to the primary line.
- **Effort:** M · **Impact:** high.

### 6. Dashboard hero TodayStrip breaks at narrow widths
- **Location:** `TodayStrip.jsx:31-35`.
- **Problem:** The four-column grid is hardcoded via inline style `gridTemplateColumns: '1fr 2fr 1fr 1fr'` with no breakpoint. Between ~640 px and 900 px the Top Sellers card's 52 px rank digits crash into the SKU column, and hero revenue at 34 px truncates next to a $20k value.
- **Fix:** Wrap the grid in a responsive class string (stack to 1-col under `sm`, 2-col `md`, 4-col `lg`). Shrink Top Sellers numerals via a container query or clamp(28px, 5vw, 52px).
- **Effort:** S · **Impact:** high.

### 7. Give inputs a visible focus ring, not a border-color swap
- **Location:** `LoginForm.jsx:50`, `TiresDashboard.jsx:892`, `CrmPage.jsx:612/624/631/642`, `MarginFilters.jsx` search/selects, every `<select>` in `AnalyticsPage.jsx` and `OrdersList.jsx` modals.
- **Problem:** Current pattern is `focus:border-zinc-500` on a `border-zinc-700` input - a 1 px color shift in dark values most users cannot see, and it fails 3:1 non-text contrast against the dark surface. Keyboard users have no reliable "where am I" signal.
- **Fix:** Add `focus-visible:ring-2 focus-visible:ring-amber-500/60 focus-visible:ring-offset-0 focus-visible:border-amber-500` as a shared `INPUT_FOCUS` token, apply globally via a Tailwind layer rule for `input, select, textarea`.
- **Effort:** S · **Impact:** high (a11y).

### 8. Status + fulfillment badges: pick one geometry
- **Location:** `OrdersList.jsx:146-161` (rounded-full pills), `Dashboard.jsx:207/234` (rounded-full pills at 10 px), `QueueRow.jsx:23` (rounded-full), `MarginTable.jsx:58` (rounded-md listing chips), `PeopleDashboard.jsx` crew tags (no pill at all).
- **Problem:** In a single vertical scan a user sees rounded-full, rounded-md, and bare text treatments for status-equivalent information; the cancelled gray pill in `statusBadge` even doubles as the fallback for unknowns, so "Unknown" and "Cancelled" look identical.
- **Fix:** Extract a `<StatusPill tone kind>` primitive with one radius (rounded-full), one set of 6 tones (amber/emerald/sky/violet/rose/zinc), and an explicit neutral for "unknown" that is visually distinct from "cancelled" (e.g. dashed border, no fill).
- **Effort:** M · **Impact:** med.

### 9. Modal dismissal is inconsistent across the app
- **Location:** `OrdersList.jsx:782-838` (has ESC + backdrop dismiss + close button); `BulkCtsModal.jsx:33-39` (ESC only, no backdrop dismiss); `PermissionEditor.jsx` (via `UserEditorModal`); `InvitePreviewModal`; `InputPromptModal`.
- **Problem:** Three modals close on backdrop-click, two do not; two label the close affordance "Close", one says "Cancel". Users who learn one pattern get trapped by the next.
- **Fix:** Standardize on the `modalChrome.js` primitives already in the repo - backdrop click dismisses unless `busy`, ESC always dismisses, visible close glyph top-right in every panel, consistent label "Close".
- **Effort:** M · **Impact:** med.

### 10. Empty states are a mix of bespoke SVGs, string literals, and the `EmptyState` component
- **Location:** `EmptyState.jsx` exists and is used in `OrdersList.jsx:541`, `MyQueuePage.jsx:83`, `PeopleDashboard.jsx:592`. Meanwhile `Dashboard.jsx:179`, `HiddenGemsSurface.jsx:31`, `CrewDirectoryWidget.jsx:69`, `CrmPage.jsx:691`, `AnalyticsPage.jsx:459/604/632`, `TiresDashboard.jsx:508` all roll their own one-line empty states.
- **Problem:** On a fresh install the user sees five different "nothing here yet" voices in one session. Some have CTAs, some don't; some have icons, some don't.
- **Fix:** Sweep bespoke empties into the shared `EmptyState` (add a `compact` variant for card-sized empties like Hidden Gems). Adopt one microcopy template: headline + 1-line why + optional CTA.
- **Effort:** M · **Impact:** med.

## 3. Quick wins

- `Dashboard.jsx:154` - "Live counts unavailable right now - showing zeros" is the only user-facing hyphen-as-dash in the hero area. Swap to an en-dash or break into two sentences; current wording reads like a stack trace.
- `TiresDashboard.jsx:1005` - The check glyph in the "Sort: Opportunity" button is redundant with `aria-pressed` + the amber active style. Drop the glyph.
- `ActivityTicker.jsx:38-49` - Inline `<style>` tag per mount injects the same 10-line rule repeatedly. Move to `index.css`.
- `OrdersList.jsx:682,700` - Emoji-prefixed labels collide with the otherwise icon-free dark aesthetic. Either commit to emoji or move to SVGs; mixing is jarring.
- `AnalyticsPage.jsx:453/531/688` - Same "Showing the 4,000 most recent…" banner repeats verbatim three times. Extract `<SampleCapBanner count={4000} />`.
- `CrmPage.jsx:644-648` - The "Lost · N" counter floats at the end of the filter row with no visual separator from the inputs. Put it in a right-aligned chip to match the pipeline summary row below.
- `TopSellersCard.jsx:88-100` - The `SOLD` caption is absolutely positioned with `left: -20; right: -20` to break out of the 96 px container. Works but is fragile; replace with `grid-template-areas`.
- `LoginForm.jsx:39/54` - Labels are `text-zinc-500` (muted) while inputs are `text-zinc-100`. Label text should be brighter than placeholder. Bump to `text-zinc-300`.
- `MarginFilters.jsx:87` - `accent-zinc-200` on the min-margin slider renders almost invisible on dark. Switch to `accent-amber-400` to match the haggle slider.
- `ModuleSubheader.jsx:15` - `sm:text-3xl max-sm:text-xl` with `text-2xl` base means mobile < 640 px renders at the smallest size, tablet at 24 px, desktop at 30 px - a non-monotonic step because `max-sm` and `sm:` are evaluated independently. Drop `max-sm:text-xl` and let `text-2xl` be the mobile base.

## 4. Systemic issues

- **Radius drift.** `rounded-xl` (cards in Dashboard/Orders), `rounded-2xl` (Tires filter panel, Analytics metric cards, queue rows, People table section), `rounded-lg` (buttons, popovers), `rounded-md` (listing chips, archive pager). No documented rule for which size belongs to which density tier.
- **Opacity soup.** `bg-zinc-900/30`, `/35`, `/40`, `/50`, `/60`, `/65`, `/70`, `/80`, `/90`, `/95` all appear - the light-theme override block in `index.css` had to enumerate every single value. This is a symptom: surfaces should have three tiers, not ten.
- **Duplicated utility strings.** The sticky-column actions cell in PeopleDashboard and the sticky-column "Reference" in OrdersList each hand-roll `shadow-[-6px_0_10px_-4px_rgba(0,0,0,0.45)]`. Same rule for the amber "active filter" chip variant: `bg-amber-950/70 text-amber-100 ring-1 ring-amber-800/50` appears in TiresDashboard, PeopleDashboard timed-elevation badge, OrdersList pricing-anomaly chip.
- **Inline styles leak past the Tailwind surface.** `Dashboard.jsx:122`, `TodayStrip.jsx:34`, `TopSellersCard.jsx:58/80/90` all bypass the design system. These should become classes in `index.css` or a component variant, otherwise future theme work (light mode, high-contrast mode) has to maintain JS and CSS in parallel.
- **Mixed currency/number primitives.** `formatCurrency`, `formatCurrencyOrDash`, `formatQty`, `formatPercent`, and raw `.toFixed(1)` (`AnalyticsPage.jsx:474/481/741`) coexist. Pick one and delete the rest.

## 5. A11y gaps

- `OrdersList.jsx:137-143`, `CrmPage.jsx:1177-1183`, `QueueRow.jsx:14` - status conveyed by color alone on small text. Add a leading dot or label prefix so colorblind users aren't guessing.
- `TopSellersCard.jsx` - The entire card auto-rotates every 3 s with no pause control beyond hover and no focus handling. Keyboard users cannot stop it. Add a focus-visible pause and respect `prefers-reduced-motion`.
- `ActivityTicker.jsx` - 35 s scroll with no reduced-motion guard; hover pauses but focus does not. Wrap the `@keyframes` in a `@media (prefers-reduced-motion: no-preference)` block.
- `MarginTable.jsx:48-77` - Listing-status platform chips use `title` attributes for the difference between "active", "stale", "never posted". Screen readers get the short code `FB` only. Add an `aria-label` like `Facebook listing active, posted 3 days ago`.
- Focus ring is essentially invisible on every input (see Top-10 #7). Compound this with `focus:outline-none` that appears in ~40 call sites without a replacement ring.
- `CrmPage.jsx:778-803` kanban cards have `role="button"` with keyboard handlers, but the card also contains interactive children in mobile view. Use a real `<button>` wrapping the non-interactive content and let child buttons be siblings.
- `Dashboard.jsx:131` - decorative grid background lacks an explicit `aria-hidden`; lint tooling flags this even though SRs ignore background images.
- `AnalyticsPage.jsx:494` uses a raw flame emoji as the only indicator of streak heat with no textual equivalent; the size change (`flameSize`) is lost entirely. Add `aria-label="streak heat N days"`.
- `TiresDashboard.jsx:947-961` - the haggle-discount range input is hidden under `sm:inline-flex` on small screens. Provide a text-input fallback or keep visible with a numeric stepper.
- Tab order in the Tires selection action bar jumps around because action buttons share the same DOM row with "Clear selection" on the right - TAB does not follow visual reading order. Consider a logical grouping with `<ul role="toolbar">`.

## 6. Out of scope / not worth fixing

- **Light-theme override block in `index.css:193-625`.** It is an ugly sea of `!important` mappings, but it works, is isolated, and rewriting it would touch ~1000 call sites. Leave it until a deliberate design-token migration.
- **Top Sellers 3-second auto-rotate.** It's a considered choice by the Precision Cockpit spec; only add a pause affordance (above) and move on.
- **Multi-stage kanban drag-and-drop keyboard handling (`CrmPage.jsx:787-802`).** Arrow-keys-to-move is already better than most kanban boards ship with; a full dnd-kit rewrite is not worth the risk right now.
- **Per-module header sign-out (`PeopleDashboard.jsx:715/719`).** Duplicated header chrome exists because People is still semi-standalone. Fixing this is a navigation refactor, not a polish task.
- **The `sk-beast-pulse` and `sk-credit-flash` animations in `index.css:113-119`.** Used sparingly, reinforce the "cockpit" character, and cost effectively nothing.
